JEOWEB SCRIPT INDEX
===================

This file lists the main import/repair scripts in this workspace and what each one does.

1) Website / HTML5 / Flash importer
----------------------------------
File: import-flash.ps1
Purpose: Imports a website game from a URL into Assets/ and updates the site lists.
Supports: Single import and batch import.
Also now auto-recovers common missing runtime files during import, including:
- mirrored Poki Unity Build files
- secondary Poki SDK files
- Godot manifest / icon / service worker files
- Defold archive manifests and archive piece files
Batch file: flash-batch.txt
Batch format: URL | Game-Name
Example:
  pwsh ./import-flash.ps1 --batch ./flash-batch.txt

File: import-flash.sh
Purpose: Shell version of the website importer.
Use when running from bash instead of PowerShell.

2) Batch website import list
----------------------------
File: flash-batch.txt
Purpose: Queue multiple web game URLs for import-flash.ps1.
Format:
  https://example.com/game/index.html | My-Game-Name

3) GBA ROM import
-----------------
File: import-gba.sh
Purpose: Imports one GBA ROM into the site.

File: import-gba-batch.sh
Purpose: Batch import multiple GBA ROMs.
Use when dropping many .gba files at once.

4) SNES ROM import
------------------
File: import-snes.sh
Purpose: Imports one SNES ROM into the site.

File: import-snes-batch.sh
Purpose: Batch import multiple SNES ROMs.
Use when dropping many .smc/.sfc files at once.

6) Site scanner
---------------
File: scan.js
Purpose: Scans Assets/ and regenerates games_list.json.
Run:
  node ./scan.js

6b) Maintenance flag toggle
---------------------------
File: scripts/maintenance-toggle.js
Purpose: One-shot heal/break/clear of any slug. Updates maintenance_overrides.json
  so the homepage updates after the next health refresh.
Run:
  node scripts/maintenance-toggle.js heal  bloons-player-pack2
  node scripts/maintenance-toggle.js break some-actually-broken-game
  node scripts/maintenance-toggle.js clear some-slug
  node scripts/maintenance-toggle.js list
  npm run game:heal -- bloons-player-pack2

6c) Triage / repair broken recents
----------------------------------
File: scripts/fix-broken-recents.js
Purpose: Walks recently_added.json and classifies each entry as
  EMPTY (delete), ETHANYO_TRAP (hide + stub), REBASEABLE (rewrite
  <base href> + absolute /assets paths to local archive),
  UNRECOVERABLE_BASE (hide), PSEUDO_GAME (hide), or OK. After
  --apply, runs scan.js to refresh the catalog.
Idempotent: rerunning is safe.
Run:
  node scripts/fix-broken-recents.js                 # dry run
  node scripts/fix-broken-recents.js --apply
  node scripts/fix-broken-recents.js --apply --only=brawl,balatro
  npm run game:fix-recents:dry
  npm run game:fix-recents

6d) Cover generator
-------------------
File: scripts/generate-cover.js
Purpose: Writes a deterministic gradient SVG cover for any slug
  missing one. Palette is derived from the slug name so the same game
  always gets the same colors. --all-missing scans recently_added.json
  and games_list.json and fills every game whose current cover is
  notavailable.svg, an ethanyo placeholder, or a missing/sub-2KB file.
Run:
  node scripts/generate-cover.js balatro "Balatro"
  node scripts/generate-cover.js --all-missing
  npm run game:cover:fill

9) Recommended workflow
-----------------------
- Import website games with import-flash.ps1 or import-flash.sh
- Batch website imports with flash-batch.txt
- Import emulator ROMs with import-gba-batch.sh or import-snes-batch.sh
- Repair broken imports with `npm run recover:all` (canonical) or `npm run recover -- <slug>` for a single game
- Rebuild the catalog with scan.js
- Refresh health verdicts with `npm run health:refresh`
- Test locally with server.js

10) Canonical recovery engine (Node.js)
---------------------------------------
File: scripts/recover-game.js
Purpose: Canonical single-game recovery. Searches the open web for a working copy of the named game across many search backends (DuckDuckGo, Brave, Bing, GitHub Code Search, Wayback), scores candidate URLs against a hand-editable domain reputation list, scrapes the top candidates with header-spoofing Puppeteer into a sandbox folder, validates with the offline manifest verifier and the Playwright scanner, then atomically swaps the live game folder when a candidate passes. Failures bump a per-slug cooldown.
Run:
  node scripts/recover-game.js <slug>
  node scripts/recover-game.js <slug> --url <portal-url>
  node scripts/recover-game.js <slug> --verbose
  node scripts/recover-game.js <slug> --ignore-cooldown

File: scripts/recover-all-broken.js
Purpose: Batch driver for recover-game.js. Reads game_health.json, filters out cooldown'd slugs, runs the recovery pipeline across all currently-broken games in parallel workers, writes reports/recovery_summary_<date>.json.
Run:
  node scripts/recover-all-broken.js --workers 3 --time-budget 90m

File: scripts/recovery/search-engines.js
Purpose: Candidate-URL discovery layer. Runs DDG/Bing/Brave/GitHub/Wayback in parallel and builds ~18 query variants per game.

File: scripts/recovery/scrape-engines.js
Purpose: Header-spoofing Puppeteer scrape into Assets/.recovery/<slug>-<ts>/. Builds on scripts/deep-asset-scraper.js.

File: scripts/recovery/atomic-swap.js
Purpose: rankCandidates() + quarantine + swap logic. Hand-editable trust list lives in scripts/recovery/domain-reputation.json.

11) Health pipeline
-------------------
File: scripts/static-health-scan.js
Purpose: Fast deterministic offline-readiness pass. Runs on every CI push. Writes static_health.json.

File: scripts/build-game-health.js
Purpose: Merges static + headless + smoke signals + overrides into canonical game_health.json (schema 2). Single source of truth the frontend reads.

File: scripts/build-offline-manifest.js
Purpose: Builds Assets/<slug>/.offline-manifest.json for one game or the whole catalog. Used as the gate for "is this game self-contained?".
Run:
  node scripts/build-offline-manifest.js --all
  node scripts/build-offline-manifest.js --slug snake

File: scripts/verify-offline-manifest.js
Purpose: CI gate. Exits non-zero if any game has a required file missing or a new external runtime dep that isn't on the allowlist. Wired into static.yml so broken games can't deploy.
Run:
  node scripts/verify-offline-manifest.js
  node scripts/verify-offline-manifest.js --candidate Assets/.recovery/snake-2026...

File: scripts/localize-all-games.js
Purpose: Sweep the catalog and (1) auto-inject /poki-offline-shim.js into HTML that references PokiSDK, (2) stub out script tags pointing at known runtime hosts (poki/gamemonetize/kongregate). Rebuilds the manifest for each game touched.
Run:
  node scripts/localize-all-games.js          # dry run
  node scripts/localize-all-games.js --apply

File: scripts/detect-broken-games.js
Purpose: Headless QA helper that launches games locally in a headless browser. Diagnostic only — does not mutate the catalog.
Run:
  node scripts/detect-broken-games.js

File: scripts/deep-asset-scraper.js
Purpose: Puppeteer deep downloader for protected sources. Used inside the recovery engine's scrape stage; can also be invoked directly for manual debugging.
Run:
  node scripts/deep-asset-scraper.js <Portal_URL> <Game_Slug>

12) Automated testing & scanning (Python)
-----------------------------------------
Prerequisites:
  pip install playwright
  playwright install chromium

File: test_performance.py
Purpose: Lightweight safety check for low-end PCs. Tests the first 5 games to ensure the system can handle headless browser automation.
Run:
  python test_performance.py

File: broken_game_scanner.py
Purpose: Comprehensive offline-readiness scanner. Detects true hard-failure breakage (missing critical local assets, runtime startup failures, and blocking external dependencies).
Features:
  - Outputs broken_games.txt and broken_games.json for hard failures only.
  - Outputs needs_review_games.txt for warnings and working_games.txt for clean games.
  - Saves full structured results to scan_results.json.
  - Optional marker sync via --sync-markers.
  - Persistent resume/checkpoint support via --resume and --state-file.
  - The --root <path> flag is used by the recovery engine to validate a candidate folder before swap.
  - The --only-from <json> flag reads slugs to scan from a recovery summary / health file.
Run:
  python broken_game_scanner.py
Resume from last checkpoint:
  python broken_game_scanner.py --resume
Use a custom checkpoint file:
  python broken_game_scanner.py --resume --state-file scan_state.json

File: deep_scan_games.py
Purpose: Strict validation tool to ensure games are 100% offline-ready and air-gapped.
Features:
  - Blocks and logs all external network requests (CDNs, analytics, APIs).
  - Saves a list of verified offline games to working_games.txt.
Run:
  python deep_scan_games.py
