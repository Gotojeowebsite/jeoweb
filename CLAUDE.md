# Jeoweb — Developer Reference

Jeoweb is a static-first, self-hosted unblocked-games portal with a Node server for local development and a large Python/PowerShell/Node automation pipeline for importing, repairing, and archiving games.
Deployment targets: GitHub Pages (`.github/workflows/static.yml`) and Azure Static Web Apps (`.github/workflows/azure-static-web-apps-ashy-desert-01fe68c10.yml`).

## Purpose

Jeoweb provides a reproducible, offline-friendly catalog of browser and retro games (596 titles as of 2026-05) with tooling for importing, repairing, and archiving. This document explains the repo layout, common commands, automation pipeline, and contribution conventions.

## Quick links

- Live site: https://jeoweb.app/
- Repository: https://github.com/Gotojeowebsite/jeoweb
- CI: `.github/workflows/static.yml` (runs `node scan.js` → `static-health-scan.js` → `build-game-health.js` before Pages deploy)

## At-a-glance commands

### Dev server and catalog

```bash
npm start                  # server.js on port 3000; rescans Assets/ every 30s, serves /api/games
npm run game:scan          # Regenerate games_list.json + recently_added.json (CI runs this)
npm run health:refresh     # game:scan + static-health-scan + build-game-health (full pipeline)
npm run health:static      # Offline-readiness pass only (scripts/static-health-scan.js)
npm run health:build       # Rebuild game_health.json (scripts/build-game-health.js)
```

### Import

```bash
npm run game:add           # scripts/add-game.js — interactive CLI
npm run grab               # scripts/grab-game.js — URL grab
npm run game:download      # scripts/download-game.js
npm run game:import-full   # python3 import_game_from_url.py — full URL importer
npm run flash:import       # pwsh import-flash.ps1 (add --batch ./flash-batch.txt for bulk)
bash ./import-gba-batch.sh # Drop .gba files in repo root first
bash ./import-snes-batch.sh# Drop .smc files in repo root first
```

### Repair / QA

```bash
npm run fix:bot            # scripts/auto-fix-bot.js — Node.js repair daemon
npm run fix:bot:dry        # Dry-run (no changes written)
npm run game:heal <slug>   # Mark game healthy via scripts/maintenance-toggle.js
npm run game:break <slug>  # Mark game broken
npm run game:maintenance:list  # List all maintenance-flagged games
npm run game:offline:audit # Audit offline readiness
npm run game:offline:fix   # Apply offline fixes
npm run game:fix-recents   # Fix broken entries in recently-played list
python3 broken_game_scanner.py   # Canonical scanner → scan_results.json
python3 auto_fix_and_recover_games.py  # Supervisor → maintenance_status.json
node scripts/deep-asset-scraper.js <URL> <slug>  # Puppeteer deep downloader
pwsh ./chaos-batch-runner.ps1  # Chaos Monkey archival pipeline
```

### Cover images

```bash
npm run covers:audit       # Dry-run cover check
npm run covers:fix         # Apply cover fixes (python3 fix_game_covers.py --apply)
npm run game:cover         # Generate cover for a single game
npm run game:cover:fill    # Fill all missing covers
```

### Media (Git LFS)

```bash
npm run media:init         # Install Git LFS + pre-commit hooks
npm run media:ingest       # Move inbox/ → library/, update media_catalog.json
npm run media:validate     # Validate media_catalog.json
```

## Architecture

### Frontend

Vanilla JS SPA: `index.html` + `app.js` (class `App`) + `assets/css/style.css`. No framework, no build step.

Features: carousels, search, filters, favorites (localStorage), recently played, theme/accent/layout customization, tab cloaker, service worker (`sw.js`), and `poki-offline-shim.js` to neutralize Poki SDK calls.

Status resolution in `app.js` (`resolveMaintenanceStatusMap` / `resolveScanStatusMap`):
1. `maintenance_status.json` — highest authority (supervisor output)
2. `scan_results.json` — scanner fallback
3. `games_list.json` `status` field — final fallback (from `<!--GAME BROKEN-->` marker in HTML)

### Local dev server (`server.js`)

Plain Node HTTP server using only built-ins. Key routes:

| Route | Behavior |
|---|---|
| `/` / `/index.html` | Inlines `window.GAMES_LIST` for dev |
| `/api/games` | Returns JSON of a fresh rescan |
| Static assets | Broad MIME map: `.wasm`, `.unityweb`, `.swf`, `.data`, fonts, audio, video |

Pre-compressed siblings: serves `Content-Encoding: br` / `gzip` when `.br` / `.gz` siblings exist.

### Assets contract

Each game lives in `Assets/<slug>/` containing:
- An HTML entry (`index.html` preferred; scanner picks the first `.html` if absent).
- A cover image — scanner priority: `logo` → `icon` → `splash` → `thumb` → `thumbnail` → folder name match.
- Optional HTML markers:
  - `<!--REQUESTED GAME-->` → sets `requested: true`
  - `<!--GAME BROKEN-->` → sets `status: "broken"`

**Type inference** (scan.js):
- Any `.swf` present → `type: "flash"`
- HTML contains `EJS_pathtodata = '/emulatorjs/'` → `type: "retro"` (core from `EJS_core` var: `gba`, `snes`, etc.)
- Otherwise → `type: "webgl"`

After adding, renaming, or changing a game folder, run `node scan.js` (or restart `server.js`) for the catalog to update. CI runs `scan.js` automatically on push to main.

### Service worker (`sw.js`)

Cache name: `jeoweb-pwa-cache-v3`.
- Static assets: cache-first.
- `/Assets/` routes: network-first (always fresh).
- Never cached (streamed directly): `.unityweb`, `.wasm`, `.data`, `.pck`, `.mem`, `.symbols`, `.nes`, `.smc`, `.gba`, `.bin`, `.iso`, `.zip`, `.7z`, `.rar`

Streams download byte counts back to the frontend (progress bar), throttled to 100 ms.

## Automation pipeline

### Importers

Normalize sources into `Assets/<slug>/`:
- `import-flash.ps1` — Flash batch importer
- `import_game_from_url.py` — URL-based full importer
- `scripts/grab-game.js`, `scripts/download-game.js`, `scripts/add-game.js`

### Recovery / Chaos Monkey

`verify_game.py` (quarantine + 404 logging) + `auto_play.py` (Playwright bot) → `missing_assets.txt`; patch scripts rehydrate assets.

`pwsh ./chaos-batch-runner.ps1` — full Chaos Monkey pipeline (quarantine server + Playwright + patch).

### Deep scrapers

`scripts/deep-asset-scraper.js` — Puppeteer-based; intercepts WebAssembly/Unity/Godot streams and spoofs headers for protected sources.

### QA / remediation

`broken_game_scanner.py` (canonical, multi-threaded scanner with resume via `scan_state.json`) → `scan_results.json`, `broken_games.json`.

`auto_fix_and_recover_games.py` (supervisor) → `maintenance_status.json`. Uses `recovery_sources.json` providers; fast-fails on dead hosts after 3 consecutive failures per run (`dead_host_cache` in summary). Prevents concurrent runs via `.auto_fix_and_recover.lock`.

`scripts/auto-fix-bot.js` — Node.js repair daemon; dry-run with `--dry-run`.

`scripts/remediation.js` — self-heal strategies.

`triage_unresolved.py` — triages `scan_results.json` + supervisor summary into `reports/triage.json` with recommended strategy per game.

### Repair scripts

`repair-games.sh`, `fix_game_covers.py` — idempotent, safe to rerun.

## Status authority & provider config

**Status resolution order** (frontend, highest to lowest):
1. `maintenance_status.json` (supervisor)
2. `scan_results.json` (scanner)
3. `games_list.json` `status` field (HTML markers via scan.js)

**Only** `broken_game_scanner.py` and `auto_fix_and_recover_games.py` may write to `scan_results.json` and `maintenance_status.json`. `scripts/qa.js` and `scripts/qa-tester.js` are diagnostic-only — they write `reports/qa_diagnostics.json` and never mutate catalog files.

**Provider config** (`recovery_sources.json`):
```json
[
  {
    "name": "example-provider",
    "type": "pattern",
    "url_template": "https://example.com/{slug}/index.html",
    "priority": 10,
    "disabled": false,
    "health_probe_url": "https://example.com/",
    "applies_to": ["webgl", "flash"]
  }
]
```

**Manual overrides** (`maintenance_overrides.json`):
```json
{
  "force_healthy": ["slug-a"],
  "force_maintenance": ["slug-b"]
}
```

Edit and then re-run `auto_fix_and_recover_games.py` (or manually regenerate `maintenance_status.json`) to apply. Commit the override with a rationale in the commit message.

## Pipeline artifacts (do not hand-edit)

These files are regenerable checkpoints written by pipeline scripts. Do not hand-edit unless curating:

- `games_list.json`, `recently_added.json` — written by `scan.js`
- `scan_results.json`, `broken_games.json`, `broken_games.txt` — written by `broken_game_scanner.py`
- `maintenance_status.json` — written by `auto_fix_and_recover_games.py`
- `game_health.json`, `static_health.json` — written by health build scripts
- `auto_fix_recovery_log.jsonl`, `auto_fix_bot.jsonl` — runtime logs
- `auto_fix_bot_summary.json`, `auto_fix_recovery_summary.*.json` — run summaries
- `scan_state.json` — scanner resume checkpoint
- `reports/triage.json`, `reports/qa_diagnostics.json` — pipeline reports
- `tmp_*.json`, `tmp_*.txt` — temporary intermediate states (safe to delete)

**Hand-edit allowed:** `maintenance_overrides.json`, `recovery_sources.json`, `slug_aliases.json`

## Conventions and rules

- **No frontend frameworks.** Keep the frontend dependency-free (vanilla JS only).
- **server.js uses Node built-ins only.** No npm dependencies in the server.
- **Mark/unmark games** by editing HTML markers + running `node scan.js`. Prefer `npm run game:heal <slug>` / `npm run game:break <slug>` for the maintenance layer.
- **Media files:** use Git LFS; pre-commit hook rejects non-LFS files >20 MB. Run `npm run media:init` after cloning.
- **CI gate:** `node scan.js` must succeed locally before pushing. The GitHub Pages deploy runs it as the first CI step.
- **New scripts:** add an entry to `scripts-index.txt` with the script's purpose and idempotency status.
- **Concurrent supervisor runs** are blocked by `.auto_fix_and_recover.lock`. Delete it if a previous run crashed without cleanup.

## Quickstart: add a game

1. Create `Assets/<slug>/` folder.
2. Add `index.html` (or first `.html`) and a cover image named `logo`, `icon`, `splash`, `thumb`, or `thumbnail` if possible.
3. Add `<!--REQUESTED GAME-->` or `<!--GAME BROKEN-->` markers if relevant.
4. Run `npm run game:scan` and verify the entry appears in `games_list.json`.
5. Commit the new folder and push.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Game shows broken in UI | `python3 broken_game_scanner.py --only <slug>`, then inspect `reports/triage.json` |
| Missing assets / 404s | `node scripts/deep-asset-scraper.js <URL> <slug>` or `pwsh ./chaos-batch-runner.ps1` |
| Ruffle broken (Flash) | Ensure `Assets/<slug>/ruffle/` exists and the HTML loads the vendored Ruffle build |
| Large file blocked by pre-commit | Add to Git LFS: `git lfs track "*.ext"` then `npm run media:init` |
| Supervisor won't start (lock file) | Delete `.auto_fix_and_recover.lock` if no supervisor is running |
| CI fails on scan.js | Run `node scan.js` locally and fix any reported errors before pushing |
| game_health.json stale | Run `npm run health:refresh` to rebuild the full health pipeline |
