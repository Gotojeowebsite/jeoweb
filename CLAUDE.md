# Jeoweb — Developer Reference

Jeoweb is a static-first, self-hosted unblocked-games portal with a Node server for local development and a large Python/PowerShell/Node automation pipeline for importing, repairing, and archiving games.
Deployment targets: GitHub Pages (`.github/workflows/static.yml`) and Azure Static Web Apps (`.github/workflows/azure-static-web-apps-ashy-desert-01fe68c10.yml`).

## Purpose

Jeoweb provides a reproducible, offline-friendly catalog of browser and retro games (596 titles as of 2026-05) with tooling for importing, repairing, and archiving. This document explains the repo layout, common commands, automation pipeline, and contribution conventions.

## Quick links

- Live site: https://jeoweb.app/
- Repository: https://github.com/Gotojeowebsite/jeoweb
- CI: `.github/workflows/static.yml` (runs `node scan.js` → `static-health-scan.js` → `build-game-health.js` before Pages deploy)

## At-a-glance commands

### Dev server and catalog

```bash
npm start                  # server.js on port 3000; rescans Assets/ every 30s, serves /api/games
npm run game:scan          # Regenerate games_list.json + recently_added.json (CI runs this)
npm run health:refresh     # game:scan + static-health-scan + build-game-health (full pipeline)
npm run health:static      # Offline-readiness pass only (scripts/static-health-scan.js)
npm run health:build       # Rebuild game_health.json (scripts/build-game-health.js)
```

### Import

```bash
npm run game:add           # scripts/add-game.js — interactive CLI
npm run grab               # scripts/grab-game.js — URL grab
npm run game:download      # scripts/download-game.js
npm run game:import-full   # python3 import_game_from_url.py — full URL importer
npm run flash:import       # pwsh import-flash.ps1 (add --batch ./flash-batch.txt for bulk)
bash ./import-gba-batch.sh # Drop .gba files in repo root first
bash ./import-snes-batch.sh# Drop .smc files in repo root first
```

### Repair / QA

```bash
# === Canonical detection ===
python3 broken_game_scanner.py     # Playwright in-browser scanner → scan_results.json
npm run health:refresh             # scan.js + static-health-scan + build-game-health
node scripts/build-game-health.js  # Merge signals → game_health.json (canonical verdict)

# === Canonical repair: NEW aggressive open-web search-and-replace ===
npm run recover -- <slug>          # find a working copy on the web, validate, swap in
npm run recover -- <slug> --url <portal-url>  # manual URL — skip search
npm run recover:all                # batch: fix every broken slug in game_health.json
npm run recover:all -- --workers 3 --time-budget 90m

# === Offline manifest gate ===
npm run offline:manifest           # build Assets/<slug>/.offline-manifest.json for every game
npm run offline:verify             # CI gate: fail if any required file is missing
npm run offline:localize           # auto-inject Poki shim + stub external runtime refs

# === Maintenance overrides ===
npm run game:heal <slug>           # mark healthy in maintenance_overrides.json
npm run game:break <slug>          # mark broken in maintenance_overrides.json
npm run game:maintenance:list      # list all flagged games

# === Diagnostics / cover gen ===
npm run game:fix-recents           # fix broken entries in recently-played list
npm run game:offline:audit         # diagnostic only — doesn't mutate

# === Legacy paths (kept for manual debugging — NOT the canonical repair path) ===
node scripts/deep-asset-scraper.js <URL> <slug>  # legacy: header-spoof scraper (now reused inside recover-game.js)
```

**The new aggressive recovery engine is the canonical repair path.** When a game is broken, `recover-game.js` searches DuckDuckGo / Brave / Bing / GitHub Code Search / Wayback for working copies on the open web, scrapes the top-scoring candidates with header-spoofing Puppeteer into `Assets/.recovery/<slug>-<ts>/`, validates with the manifest verifier and the Playwright scanner, then **atomically swaps** the broken folder out (preserving the original under `Assets/.quarantine/`) — the live `Assets/<slug>/` is only modified after a fully validated working copy exists. Failures bump a per-slug cooldown in `reports/recovery_cooldown.json` (1d → 3d → 7d → 14d → 30d backoff).

The previous in-place patch supervisor (`auto_fix_and_recover_games.py` + `scripts/auto-fix-bot.js`) and the Chaos Monkey pipeline (`chaos-batch-runner.ps1` + `verify_game.py` + `auto_play.py`) were deleted in favor of the recovery engine — they left games in a worse half-broken state when patching failed partway through.

To add new portals the recovery engine should trust, edit `scripts/recovery/domain-reputation.json` (hand-editable; higher = more preferred).

### Cover images

```bash
npm run covers:audit       # Dry-run cover check
npm run covers:fix         # Apply cover fixes (python3 fix_game_covers.py --apply)
npm run game:cover         # Generate cover for a single game
npm run game:cover:fill    # Fill all missing covers
```

```bash

npm run media:ingest       # Move inbox/ → library/, update media_catalog.json
npm run media:validate     # Validate media_catalog.json
```

## Architecture

### Frontend (in transition)

Two trees coexist during the rebrand rollout (see `/root/.claude/plans/look-at-my-website-vivid-flamingo.md`):

**Legacy (currently shipped):** Vanilla JS SPA — `index.html` + `app.js` (class `App`) + `styles.css`. No framework, no build step. This is what `https://jeoweb.app/` serves today.

**New (Sprint 0+, in progress, not yet deployed):** Astro + Preact in `src/`. Builds to `dist/` via `npm run build`. Reads the same `games_list.json` / `game_health.json` / `recently_added.json` artifacts the legacy pipeline produces — `scan.js`, `broken_game_scanner.py`, `build-game-health.js`, the recovery engine are unchanged. Design tokens live in `src/styles/tokens.css`; new logo in `src/assets/brand/`; icon system in `src/components/icons.ts`. The `/dist` directory is gitignored. CI builds Astro on every push but the deploy artifact is still `.` (the root) until the Sprint 7 cutover.

Quick scripts: `npm run dev` (Astro dev server), `npm run build` (full static build, 596 game pages + 11 chrome pages), `npm run typecheck` (`astro check`), `npm start` (legacy Node server, unchanged).

Features: carousels, search, filters, favorites (localStorage), recently played, theme/accent/layout customization, tab cloaker, service worker (`sw.js`), and `poki-offline-shim.js` to neutralize Poki SDK calls.

Status resolution in `app.js` (`resolveMaintenanceStatusMap` / `resolveScanStatusMap`):
1. `game_health.json` — canonical merged verdict (schema 2, written by `scripts/build-game-health.js`)
2. `scan_results.json` — scanner fallback
3. `games_list.json` `status` field — final fallback (from `<!--GAME BROKEN-->` marker in HTML)

### Local dev server (`server.js`)

Plain Node HTTP server using only built-ins. Key routes:

| Route | Behavior |
|---|---|
| `/` / `/index.html` | Inlines `window.GAMES_LIST` for dev |
| `/api/games` | Returns JSON of a fresh rescan |
| Static assets | Broad MIME map: `.wasm`, `.unityweb`, `.swf`, `.data`, fonts, audio, video |

Pre-compressed siblings: serves `Content-Encoding: br` / `gzip` when `.br` / `.gz` siblings exist.

### Assets contract

Each game lives in `Assets/<slug>/` containing:
- An HTML entry (`index.html` preferred; scanner picks the first `.html` if absent).
- A cover image — scanner priority: `logo` → `icon` → `splash` → `thumb` → `thumbnail` → folder name match.
- Optional HTML markers:
  - `<!--REQUESTED GAME-->` → sets `requested: true`
  - `<!--GAME BROKEN-->` → sets `status: "broken"`

**Type inference** (scan.js):
- Any `.swf` present → `type: "flash"`
- HTML contains `EJS_pathtodata = '/emulatorjs/'` → `type: "retro"` (core from `EJS_core` var: `gba`, `snes`, etc.)
- Otherwise → `type: "webgl"`

After adding, renaming, or changing a game folder, run `node scan.js` (or restart `server.js`) for the catalog to update. CI runs `scan.js` automatically on push to main.

### Service worker (`sw.js`)

Cache name: `jeoweb-pwa-cache-v4`.
- Static assets: stale-while-revalidate.
- `/Assets/` routes: network-first, no caching of large binaries.
- Streams download byte counts back to the frontend (progress bar), throttled to 100 ms.

### Offline manifest (`.offline-manifest.json`)

Every `Assets/<slug>/` has a `.offline-manifest.json` (schema 1) generated by `node scripts/build-offline-manifest.js`. It lists every file in the folder, marks engine-critical and HTML-referenced files as `required: true`, and records the set of external hosts the game references (`external_hosts`, `external_critical`). The verifier (`scripts/verify-offline-manifest.js`) checks every required file exists at the recorded size and that no non-allowlisted external runtime dep snuck in. The CI in `.github/workflows/static.yml` runs the verifier and **fails the deploy** on any miss. Update the manifest with `node scripts/build-offline-manifest.js --slug <slug>` after any change to a game folder.

## Automation pipeline

### Importers

Normalize sources into `Assets/<slug>/`:
- `import-flash.ps1` — Flash batch importer
- `import_game_from_url.py` — URL-based full importer
- `scripts/grab-game.js`, `scripts/download-game.js`, `scripts/add-game.js`

### Recovery engine (canonical — NEW)

`scripts/recover-game.js` — primary single-game repair entry. Pipeline:
1. Resolve slug → display name + type (from `games_list.json`) + verdict (from `game_health.json`).
2. Discover candidate URLs via `scripts/recovery/search-engines.js` (DuckDuckGo HTML, Bing RSS, Brave Search API, GitHub Code Search, Wayback CDX). Skip search and use `--url <portal-url>` for a manual override.
3. Score + rank with `scripts/recovery/atomic-swap.js#rankCandidates` against `scripts/recovery/domain-reputation.json`.
4. For each top-ranked candidate, fail-fast: scrape into `Assets/.recovery/<slug>-<ts>/` with header-spoofing Puppeteer (`scripts/recovery/scrape-engines.js`, builds on `deep-asset-scraper.js`), validate via `verify-offline-manifest.js --candidate`, then `broken_game_scanner.py --root` for the gold-standard check.
5. On first passing candidate: `moveToQuarantine(slug)` → `swapInCandidate(slug, candidateRoot)` → rebuild manifest → re-scan.
6. On all-failure: bump `reports/recovery_cooldown.json` (1d → 3d → 7d → 14d → 30d backoff) and log to `reports/recovery_log.jsonl`.

`scripts/recover-all-broken.js` — batch driver. Reads `game_health.json`, filters cooldown, fans out workers, writes `reports/recovery_summary_<date>.json`. Invoked nightly by `.github/workflows/qa-nightly.yml`.

### Detection (canonical)

`broken_game_scanner.py` — Playwright in-browser scanner with resume via `scan_state.json`. Outputs `scan_results.json`, `broken_games.json`, `broken_games.txt`. The `--root <path>` flag is used by the recovery engine to validate a candidate folder before swap; `--only-from <json>` reads slugs to scan from a recovery summary / health file.

`scripts/build-game-health.js` — merges static + headless + smoke signals + overrides into the canonical `game_health.json` (schema 2). This is the single source of truth the frontend reads.

`scripts/static-health-scan.js` — fast deterministic offline-readiness pass; runs on every CI push.

### Legacy paths (deleted, kept here for archaeology)

The previous in-place patch supervisor (`auto_fix_and_recover_games.py` + `scripts/auto-fix-bot.js`), the Chaos Monkey pipeline (`chaos-batch-runner.ps1` + `verify_game.py` + `auto_play.py`), the offline-fix wrapper (`scripts/fix-offline-games.js`), `triage_unresolved.py`, and `scripts/remediation.js` have all been removed. They patched the existing folder in place, which left games in a worse half-broken state when patching failed partway through — the canonical recovery engine never mutates the live folder until a fully validated working copy exists.

`scripts/deep-asset-scraper.js` — still imported by `scripts/recovery/scrape-engines.js` for its header-spoof behavior, but no longer the canonical entry point.

### Repair scripts

`repair-games.sh`, `fix_game_covers.py` — idempotent, safe to rerun.

## Status authority & provider config

**Status resolution order** (frontend, highest to lowest):
1. `game_health.json` (canonical merged verdict — schema 2, written by `scripts/build-game-health.js`)
2. `scan_results.json` (scanner)
3. `games_list.json` `status` field (HTML markers via scan.js)

If `game_health.json` is older than 7 days the frontend degrades verdicts to `"unverified"` and logs a console warning, so deploys can't silently serve stale data.

**Writers (only these):**
- `scripts/build-game-health.js` → `game_health.json`
- `broken_game_scanner.py` → `scan_results.json`, `broken_games.*`
- `scripts/recover-game.js` → atomically swaps `Assets/<slug>/`; appends to `reports/recovery_log.jsonl` and `reports/recovery_cooldown.json`. Does **not** mutate the verdict files directly.

`scripts/qa.js` and `scripts/qa-tester.js` are diagnostic-only — they write `reports/qa_diagnostics.json` and never mutate catalog files.

Broken games are hidden from the default catalog view (`app.js` filters them out when `hideMaintenance=true`, which is on by default). Toggle "Show under-maintenance games" in settings to see them.

**Provider config** (`recovery_sources.json`):
```json
[
  {
    "name": "example-provider",
    "type": "pattern",
    "url_template": "https://example.com/{slug}/index.html",
    "priority": 10,
    "disabled": false,
    "health_probe_url": "https://example.com/",
    "applies_to": ["webgl", "flash"]
  }
]
```

**Manual overrides** (`maintenance_overrides.json`):
```json
{
  "force_healthy": ["slug-a"],
  "force_maintenance": ["slug-b"]
}
```

Edit and then re-run `npm run health:refresh` to apply. Commit the override with a rationale in the commit message.

## Pipeline artifacts (do not hand-edit)

These files are regenerable checkpoints written by pipeline scripts. Do not hand-edit unless curating:

- `games_list.json`, `recently_added.json` — written by `scan.js`
- `scan_results.json`, `broken_games.json`, `broken_games.txt` — written by `broken_game_scanner.py`
- `game_health.json`, `static_health.json` — written by health build scripts
- `qa_baseline.json` — broken-count baseline used by CI gate (refreshed by qa-nightly.yml)
- `Assets/<slug>/.offline-manifest.json` — per-game manifest (written by `scripts/build-offline-manifest.js`)
- `scan_state.json` — scanner resume checkpoint
- `reports/recovery_log.jsonl`, `reports/recovery_cooldown.json` — recovery engine state
- `reports/recovery_summary_*.json` — per-run recovery summaries
- `reports/localize_summary.json` — last localize-all-games run
- `reports/qa_diagnostics.json` — diagnostic pipeline report
- `Assets/.quarantine/<slug>-<ts>/` — pre-swap copy from the recovery engine (rollback target)
- `Assets/.recovery/<slug>-<ts>/` — in-flight candidate (cleaned on failure)

**Hand-edit allowed:** `maintenance_overrides.json`, `recovery_sources.json`, `slug_aliases.json`, `scripts/recovery/domain-reputation.json`

## Conventions and rules

- **No frontend frameworks.** Keep the frontend dependency-free (vanilla JS only).
- **server.js uses Node built-ins only.** No npm dependencies in the server.
- **Mark/unmark games** by editing HTML markers + running `node scan.js`. Prefer `npm run game:heal <slug>` / `npm run game:break <slug>` for the maintenance layer.
- **Media files:** use Git LFS; pre-commit hook rejects non-LFS files >20 MB. Run `npm run media:init` after cloning.
- **CI gate:** `node scan.js` must succeed locally before pushing. The GitHub Pages deploy runs it as the first CI step.
- **New scripts:** add an entry to `scripts-index.txt` with the script's purpose and idempotency status.

## Quickstart: add a game

1. Create `Assets/<slug>/` folder.
2. Add `index.html` (or first `.html`) and a cover image named `logo`, `icon`, `splash`, `thumb`, or `thumbnail` if possible.
3. Add `<!--REQUESTED GAME-->` or `<!--GAME BROKEN-->` markers if relevant.
4. Run `npm run game:scan` and verify the entry appears in `games_list.json`.
5. Commit the new folder and push.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Game shows broken in UI | `python3 broken_game_scanner.py --only <slug>`, then inspect `scan_results.json` |
| Missing assets / 404s | `npm run recover -- <slug>` (canonical) or `node scripts/deep-asset-scraper.js <URL> <slug>` for manual debugging |
| Ruffle broken (Flash) | Ensure `Assets/<slug>/ruffle/` exists and the HTML loads the vendored Ruffle build |
| Large file blocked by pre-commit | Add to Git LFS: `git lfs track "*.ext"` then `npm run media:init` |
| CI fails on scan.js | Run `node scan.js` locally and fix any reported errors before pushing |
| game_health.json stale | Run `npm run health:refresh` to rebuild the full health pipeline |
