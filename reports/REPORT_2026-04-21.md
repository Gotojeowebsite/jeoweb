# Maintenance + Reliability Report — 2026-04-21

## Executive summary

Tightened the reliability pipeline without touching architecture or deployment. The recovery supervisor now sorts providers by priority, honors per-provider health probes, and short-circuits on dead hosts within a run; the provider list grew from 4 near-useless patterns to 13 prioritized patterns sourced from existing repo recovery scripts. Competing status writers (`scripts/qa.js`, `scripts/qa-tester.js`) were converted to diagnostic-only, making the scanner + supervisor the single status authority. A new `triage_unresolved.py` groups the 68 unresolved games into actionable buckets (49 local-asset, 12 external-dep, 6 runtime, 1 unknown), turning an opaque "68 broken" into a per-class to-do list. Frontend received a malformed-head fix, async-only third-party scripts with error swallowing, a default-on Hide-Maintenance filter, and a scan-freshness pill — no features removed. A full end-to-end Playwright rescan was not executed in this environment (no preinstalled Chromium and a 573-game scan runs ~60 min); all changes were validated by syntax check, provider-loader smoke tests, live dev-server boot, and catalog regeneration.

## Website quality improvements delivered

- **Malformed `<head>` fixed.** `fonts.goo a\n\t\tgleapis.com` was producing a broken preconnect; Poppins now preconnects with `crossorigin` and the expected cost savings.
- **Third-party scripts no longer block startup.** All six of cmp.gatekeeperconsent, the.gatekeeperconsent, ezojs, ezoicanalytics, googletagmanager, and the inline gtag block are now `async` with `onerror` swallow. A failing consent script or ad script no longer stalls `app.js`.
- **Hide-maintenance filter (default on).** Users no longer land on the 69 under-maintenance titles on first page load. The toggle persists via `localStorage: jeo-hide-maintenance`.
- **Status freshness pill.** Reads `maintenance_status.json#generated_at`, renders "N h ago" / "N d ago" with color coding so you can see at a glance whether status data is stale.
- **Status authority is now documented and enforced.** Frontend resolution order (`maintenance_status.json` → `scan_results.json` → `games_list.json.status`) is implemented in `app.js` and documented in `OPERATIONS.md`; writers are restricted by converting the two rogue scripts to diagnostic-only.
- **Preserved.** Favorites, recently played, newly added, tab cloaker, theme/accent/background customization, search, flash/retro toggles — untouched and verified by dev-server smoke test.

## Unresolved blockers and why they remain

1. **No end-to-end scanner rerun performed.** This environment has no preinstalled Chromium and a full 573-game sequential scan is ~60 min. The existing v16 supervisor summary + `scan_results.json` were used for triage instead. To validate the expected recovery improvement, run the weekly procedure in `OPERATIONS.md`.
2. **49 local_missing_asset unresolved games.** These need `bash ./repair-games.sh` plus targeted `node scripts/remediation.js` runs; both require live network to origin hosts, which I did not exercise here to avoid making uncommitted changes to `Assets/`.
3. **Poki-CDN providers kept last but still present.** They usually 403; they earn their slot only when a poki-mirrored game is the target. A future cleanup could split provider list per game type using `applies_to` more aggressively.
4. **`scan_results.json` is partial.** It currently contains only 12 games from a prior targeted run; full rescan is pending.
5. **One `type` reclassification noticed during verification.** `node scan.js` now reports 251 flash vs 250 before, 210 webgl vs 211 before — same 573 total. Caused by scan.js type-inference (`.swf` detection) on an asset folder I did not modify; unrelated to this change set.
